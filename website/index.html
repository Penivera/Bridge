Systems architecture & ingress

Distributed. Self-aware. Fault-tolerant ingress for dynamic cloud infrastructure.

BRIDGE is a lightweight daemon (emphasis on lightweight) that runs on your VMs. It watches services spin up and down, builds an automatic routing table across your fleet, handles automatic cross-VM replication, and makes every node aware of every service, no matter where it lives.

Why BRIDGE exists

The infrastructure changes. How does the network know?

When you have several servers running different services, routing traffic to them is pure friction. Every deployment meant updating a stack of configurations across the board: SSH into the host, edit reverse proxy configs, validate syntax, reload, and hope nothing breaks in transit. Static gateway mappings become stale the moment dynamic containers move.

Worse, healthy infrastructure can still be unreachable. If an ingress bastion crashes, your application backends are running fine, but the outside world is cut off. Human-in-the-loop latency guarantees network downtime during unplanned failures—manual reconfiguration simply cannot keep up with dynamic cloud workloads.

BRIDGE eliminates that friction by making infrastructure aware of itself. A lightweight daemon on each VM watches services spin up and down, forms an encrypted WireGuard mesh, gossips health state, and autonomously elects an edge leader. If a leader or backend dies, traffic reroutes and the ingress hands off in milliseconds without human intervention. It makes a fleet of VMs work like one—bridging the brain, so to speak.

What it does

Everything your fleet needs, in one lightweight binary

Routing

Cross-fleet routing

One entry point, multiple servers. Ingress traffic routes point-to-point over WireGuard directly to healthy backends on any VM.

Compatibility

Plugs into your existing stack

Works alongside Traefik, Nginx, or whatever you already run. Choose L7 Direct HTTP, L4 SNI passthrough, or custom reverse proxies.

Integrations

First-class Coolify support

Managed delegation mode pairs directly with your Coolify setup to bridge nodes and route dynamic multi-server deployments seamlessly.

Discovery

Automatic routing table

Watches services spin up and down in real time. Makes every node aware of every service across your fleet, wherever it lives.

Resilience

Automatic cross-VM replication

Critical workloads can replicate to peer nodes on failure, with automatic or manual failback and configurable cooldowns.

Liveness

Self-aware SWIM gossip

Continuous heartbeat detection discovers cluster health (Alive → Suspected → Dead → Recovered), converging in seconds.

Consensus

Autonomous leader election

Bully algorithm with configurable priorities elects one ingress leader. If it dies, another takes over instantly without human latency.

Operations

Dashboard & CLI

Embedded ops console on 127.0.0.1:9090, real-time WebSocket events, JSON API, and a fast CLI over Unix socket.

Every VM runs the same lightweight BRIDGE daemon. Continuous SWIM gossip keeps node state synchronized, while leader election assigns the public ingress. If the active leader dies, another takes over instantly—continuous state, automatic decisions.

How it works

Three steps to a self-aware fleet

Install the daemon on each VM

One lightweight command per VM installs the binary, sets up a system user, and configures the systemd service.

Nodes form the mesh and elect a leader

WireGuard links connect, gossip discovers peers in seconds, and the highest-priority alive node takes the ingress.

Route seamlessly across the fleet

One entry point for multiple servers. As services spin up and down, BRIDGE updates the routing table automatically.
